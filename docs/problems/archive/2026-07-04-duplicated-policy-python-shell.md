1. **Time & Date:** 2026-07-04T06:17:34Z
2. **Name:** Networking policy rules duplicated between Python and shell (drift risk)
3. **Issue:** The same invariants are enforced independently in two languages: (a) role list, target list, and the channel-42/bandwidth-2/US rule live in both `validate.py` and `provision.sh`; (b) the "is eth0 mesh-side or WAN-side" decision is computed in `provision.sh` and again in `network.sh`.
4. **Severity:** S4 (Minor)
5. **Location:** `packages/core/src/easymanet/validate.py:14-18,286-291` vs `images/openmanet/provisioning/openwrt-overlay/usr/lib/easymanet/provision.sh:118-153`; `provision.sh:166-171` (`ETH0_MESH_SIDE`) vs `network.sh:41-54` (`easymanet_eth0_mesh_side`)
6. **Expected:** Each rule has one authoritative home. Where duplication is unavoidable (host-side Python vs on-node shell), a shared test asserts both implementations agree (the `openwrt-sim` harness can drive the shell side).
7. **Actual:** Adding a target, role, or regulatory rule requires editing Python and POSIX shell in lockstep; a missed edit fails silently — e.g. a fleet that passes `validate` but dies at first boot with a FATAL, or vice versa a first-boot script accepting what validate would reject. The eth0-side duplication is subtler: if the two copies drift, first boot and the late-boot repair (`easymanet-management-lan` init) would fight over which bridge owns eth0.
8. **Reproduction:** Not a runtime bug today — inspection finding. To see the exposure: add a hypothetical target to `VALID_TARGETS` in `validate.py` only, flash, and watch first boot exit FATAL at `provision.sh:125-131`.
9. **Notes:** From the 2026-07-04 mesh review; same drift-class as the 2026-06 finding about reverse-engineered OpenMANET UCI keys. Cheapest guard: a test in `tests/` that renders a fleet through Python and runs `provision.sh` under the shell harness, asserting accept/reject parity. For eth0-side: `provision.sh` could source `network.sh` and call `easymanet_eth0_mesh_side` instead of recomputing.
